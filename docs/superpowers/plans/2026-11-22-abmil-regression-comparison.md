# ABMIL regression comparison implementation plan

Test whether ABMIL with mean or gated-attention pooling improves MammaPrint index regression over existing slide-mean linear runs recorded in the Google Sheet. Use frozen L2 Virchow2 embeddings and validation results to choose the configuration, then report one locked model's held-out test result. Run an L1 follow-up only after the [resolution comparison](2026-11-22-l1-resolution-comparison.md) supports it. Keep new embeddings, transformers, and spatial encoding outside this work.

## 1. Freeze the cohort and Google Sheet baseline

- [ ] Snapshot the metadata and validation columns for existing L2 slide-mean linear regression runs in the Google Sheet. Record the sheet tab and rows, retrieval date, run IDs, seed and fold IDs, embedding source, split, checkpoint selection rule, and validation metric definitions. Choose the reference configuration before training ABMIL. Prefer cancer-mask-5 L2 when it has a comparable reference with at least three eligible seeds. If several comparable configurations share that source and split, use the one with the lowest mean validation MAE across eligible seeds, breaking ties by seed coverage and then config ID. Train only the ABMIL arms. Report any difference in training recipe or checkpoint selection when interpreting gains.
- [ ] Pin the reference's L2 card, source artifact versions, label mapping, eligible slide IDs, tile counts, exclusions, and split assignment for both new arms. Reuse the labeled, nonempty slide eligibility in `ml/data/datasets/single_scale.py`. Reject duplicate slide IDs, nonfinite targets, and cross-split overlap. Check patient or case overlap when a verified grouping key is available and record whether grouping could be verified. Use the existing fixed L2 split if no comparable reference can be verified and report that the baseline comparison is inconclusive.
- [ ] Reuse CV if the reference runs used it and their fold assignments can be recovered and verified. Pair methods by fold and seed, select each ABMIL checkpoint on a fixed inner validation split, and score pooled out-of-fold predictions per seed. For fixed-split runs, use the existing train and validation artifacts and report seed variability on one split. Reserve the held-out test partition in either case.

**Acceptance.** A versioned manifest identifies the Google Sheet reference runs and records the matched source, cohort, and split protocol or the provenance gap that limits the comparison. Confirm from membership metadata that test is held out before any scoring job is enabled.

## 2. Add the projector and fixed recipe

- [ ] Add `TileProjector(in_dim, out_dim, dropout)` in `ml/models/encoders/tile_projector.py` and register it with the existing encoder package and Hydra group. Apply `Linear(2560, 256) → GELU → Dropout(0.20)` to each tile. Route the projected dimension to the aggregator and `LinearHead`, preserving 2,560 as the input width. Reuse `MeanPool` and `AttentionMIL`, with a 128-wide gating layer for ABMIL-attention. Add an opt-in identity normalization path to the attention aggregator for the new preset so both pooling arms pool the same projected values. Preserve the existing attention preset's LayerNorm default.
- [ ] Add opt-in scalar head initialization to `ml/models/heads/linear.py` and wire it into a fresh regression fit in `ml/train.py`. Use Xavier uniform with gain `0.01` and set the bias to the mean index of eligible training slides, read from dataset label metadata without decoding bags. Compute this separately inside each fit partition. Apply it only when requested, before training and after verifying the targets are finite. On resume or checkpoint evaluation, restore the saved head. Use zero head dropout for all fixed-recipe arms so projector dropout is the regularizer being varied.
- [ ] Add an opt-in training-only tile cap to `SingleScaleDataset`, drawing 1,024 distinct rows uniformly without replacement on every fetch and retaining every row in shorter bags. Sample before tensor conversion and device transfer. Seed the loader shuffle and tile RNG independently of model initialization. Use the same sampling stream for matched seed and fold across fixed-recipe arms, with fresh draws across epochs. Keep validation, test, and prediction uncapped even with a training cap in the resolved config. Train on four variable-length slide bags per optimizer step with equal weight per slide. Add a separate evaluation batch size of one through `ml/data/datamodule.py`. A Parquet read still decodes a full slide. Measure host I/O and peak device memory in the pilot before optimizing the loader. If full-bag evaluation exceeds memory, use exact chunked projection and pooling with a running sum/count for mean and a numerically stable weighted sum for attention.
- [ ] Add Hydra presets under `configs/experiment/ml/` for ABMIL-mean and ABMIL-attention. Share an AdamW recipe with `lr=1.5e-4`, `weight_decay=1e-3`, MSE training loss, and epoch-wise cosine annealing over 50 epochs to `eta_min=1e-6`. Give both arms the same 50-epoch budget and save the checkpoint with lowest validation MAE, preferring the earlier epoch on a tie. Record the initial prediction mean and SD on a fixed training probe, the training target mean and SD, early validation loss, optimizer steps, LR, and best epoch.

**Acceptance.** Compose all presets and run a CPU fit, save, reload, and validation pass on synthetic variable-length Parquet bags. Check that the output is scalar, the head starts near the training label mean, a restored head retains its bias, and a four-slide batch produces one optimizer update. Test that equal-mean bags can give different outputs after projection, sampling is repeatable with a fixed seed and changes across epochs, and a one-tile or oversized evaluation bag uses all its tiles. If chunking is needed, compare full and chunked scores and attention on the same fixtures.

## 3. Run the paired validation benchmark

- [ ] Prepare `scripts/ml/run_abmil_comparison.py` to expand the frozen matrix, print the resolved commands and target, and track checkpoints and run IDs by fold, seed, and configuration. Use the same five seeds for both ABMIL arms, preferring **0, 1, 2, 3, 4** when the reference covers them. Otherwise take up to five available reference seeds in ascending order and fill any remaining slots with the lowest unused seed IDs. The core matrix uses 10 new fits on a fixed split.

  | Arm | Tile representation | Pooling | Recipe |
  | --- | --- | --- | --- |
  | Historical linear reference | Raw 2,560-wide tiles | Mean | Existing runs from the Google Sheet |
  | ABMIL-mean | Projected tiles | Mean | Fixed AdamW recipe and tile sampling |
  | ABMIL-attention | Projected tiles | Gated attention | Fixed AdamW recipe and tile sampling |

- [ ] Run a one-factor sensitivity check for each projected arm on the first two frozen seeds, against its nominal runs on those seeds. Use width **128**, dropout **0.35**, and LR **2e-4** as the three single-change variants. This adds 12 fits on a fixed split. Report paired deltas as exploratory sensitivity. Keep model selection restricted to the nominal ABMIL configs and the historical reference.
- [ ] Force `test_after_fit=false` for every comparison job because `configs/ml.yaml` enables it by default. Export checkpoint predictions using the explicit validation loader because the existing `mode=predict` path resolves to test. Add a split guard to the runner and a smoke test with a test loader that raises if accessed. Store resolved config, code and environment revision, manifest digest, seed, fold, run ID and checkpoint ID with each result. Pilot on development data and record memory, throughput and projected run cost. Verify the matrix locally before requesting explicit approval for each cluster submission with its jobs, context, namespace, resources and output paths.
- [ ] Create or update `.agents/skills/abmil-regression-comparison/SKILL.md` with the reusable launcher and evaluation commands, managed authentication, target verification, dry-run, expected artifacts, retry and cleanup. Independently review split integrity, checkpoint selection, and the evaluation guard before the full benchmark. Verify and commit the remote workflow scripts and skill together.

**Acceptance.** A local dry-run enumerates the expected matrix and refuses test access. Every approved validation fit yields a best checkpoint and a complete prediction export on the frozen cohort. Retries reuse the same manifest, fold, seed and resolved overrides.

## 4. Score predictions and check attention

- [ ] Implement shared regression scoring in `ml/metrics/regression.py` and export per-slide `slide_id`, target, raw score, fold, seed, and tile count with `scripts/ml/evaluate_abmil_comparison.py`. Compute MAE, MSE, Spearman on continuous targets and scores, and sign-AUROC with `target >= 0` as the positive class and the raw predicted index as the ranking score. Reuse the metric semantics from `origin/feat/concept-explainability:ml/test_evaluation.py`. Calculate rank metrics over the full evaluation cohort, with explicit undefined values and reasons for constant rank inputs or a single target class. If exposed through Hydra during training, use the same definitions for epoch-level validation and test metrics. Test that zero is positive, tied scores are handled, and missing, duplicate or unmatched prediction rows fail the comparison.
- [ ] Report validation metrics as **mean ± sample SD across five ABMIL seeds** and across the available eligible baseline seeds, with counts and individual seed scores. Compute `ABMIL − historical linear` deltas only for shared seeds and verified equivalent folds, cohorts, and metric definitions. Use comparable validation metrics from the sheet at a single identified checkpoint per run. Fill metric gaps from saved validation predictions or validation-only scoring of linked existing checkpoints. Mark missing or incompatible values as unavailable and give the reason. When both sides have per-slide predictions, bootstrap the paired MAE using 10,000 seeded resamples of patient groups where grouping is verified, or slides otherwise. Use the same resample across methods and seeds and report a 95% percentile interval conditional on the trained fits. Show cohort size, exclusions, improvement direction by seed, and separate sensitivity results.
- [ ] Evaluate attention on the full validation bags at the nominal checkpoints. Check finite nonnegative weights summing to one. Report the per-slide effective tile fraction `1 / (N * sum(w²))`, top-decile weight mass, and the seedwise distribution. Track the training trend against an initialization snapshot on a fixed development probe. Use bags with at least 20 tiles for the concentration and faithfulness gates and publish their coverage. Use the paired resampling method specified for MAE to estimate the interval for the eligible slides' faithfulness deltas.
- [ ] Adapt the deletion workflow from `origin/feat/explainability:ml/explainability/faithfulness.py` to rank by raw attention weights on projected tiles. For fractions 0%, 5%, 10%, 20%, 30%, 40%, and 50%, remove the same count of top-attention, bottom-attention, or randomly ordered tiles. Renormalize attention over the retained tiles. Use at least 20 seeded random orders per slide and compare the area under the **absolute** change in predicted index from the intact bag. Either sign can be evidence for index regression. Define faithfulness as top-removal area minus mean random-removal area and report the bottom-removal control. Test a uniform/constant control and a high-attention signal fixture. Count tied ranks consistently and verify the fast pooled deletion path against direct reruns if used.

**Acceptance.** The report reproduces from prediction and attention artifacts. The attention report shows whether weights meaningfully depart from uniform and whether deleting attended tiles changes predictions more than random deletion.

## 5. Lock the validation decision and run test once

- [ ] Freeze the proposed go rule before reading ABMIL validation scores. Require **at least 2% lower mean MAE** than the historical linear reference across at least **three matched seeds**, with improvement in at least **80%** of pairs. If paired per-slide predictions exist, require the upper 95% MAE interval to be below zero. If only comparable seed-level results exist, require improvement in every matched seed and report the missing interval. Require mean Spearman and sign-AUROC within **0.02** of the reference or better on those pairs. Missing or undefined guardrail metrics make the decision inconclusive. For ABMIL-attention also require the median of the five seedwise median effective tile fractions to be **≤ 0.90** and mean faithfulness to be positive in at least **4 of 5** seeds, with a paired bootstrap lower 95% bound above zero for the seed-averaged faithfulness.
- [ ] Select the lowest mean validation MAE among qualifying arms, using the same paired seeds and preferring mean pooling on an exact tie. If the comparable results support a no-go for both, recommend retaining the historical linear configuration. If missing provenance, pairs, or metrics prevent a decision, report it as inconclusive and keep test closed. Report the deciding comparisons, seed spread, learning curves and attention diagnostics.
- [ ] Lock the chosen config, source and split digest, the first prespecified paired seed, and the checkpoint digest before test access. Use the saved validation-selected checkpoint on the fixed split. For an ABMIL winner under CV, refit that seed on the eligible development cohort with the median selected epoch count from its folds and the prespecified schedule, then lock the refit. For a retained historical reference, use its existing checkpoint and reuse its stored held-out result if the checkpoint, split, and metric definitions match. If a fresh test score is needed, run one held-out prediction pass after explicit cluster approval if required. Publish test MAE, MSE, Spearman, and sign-AUROC once for the locked setting and keep its prediction artifact when available.
- [ ] If the L1 task succeeds, repeat the frozen validation benchmark on its registered artifacts. For a resolution comparison use the shared-slide, matched-bag L2 control defined in the L1 plan. Keep the L2 decision and single test evaluation intact.

**Done.** Both ABMIL presets run end to end. Validation results include five-seed summaries, the comparison to existing Google Sheet runs, paired differences where supported, and sensitivity checks. The report gives the attention diagnostics and the go/no-go decision. The held-out report covers the single locked setting if validation supports a decision.
