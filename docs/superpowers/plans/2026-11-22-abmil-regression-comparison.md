# ABMIL regression comparison implementation plan

Add ABMIL-mean and ABMIL-attention as regular Hydra regression experiments and run them through `ml.train`. Compare their MLflow validation results by hand with existing slide-mean linear runs in the Google Sheet. Use frozen L2 Virchow2 embeddings and validation results to choose the configuration, then report one locked model's held-out test result. Run an L1 follow-up only after the [resolution comparison](2026-11-22-l1-resolution-comparison.md) supports it. Keep new embeddings, transformers, and spatial encoding outside this work.

## 1. Freeze the cohort and Google Sheet baseline

- [ ] Snapshot the metadata and validation columns for existing L2 slide-mean linear regression runs in the Google Sheet. Record the sheet tab and rows, retrieval date, run IDs, seed and fold IDs, embedding source, split, checkpoint selection rule, and validation metric definitions. Choose the reference configuration before training ABMIL. Prefer cancer-mask-5 L2 when it has a comparable reference with at least three eligible seeds. If several comparable configurations share that source and split, use the one with the lowest mean validation MAE across eligible seeds, breaking ties by seed coverage and then config ID. Train only the ABMIL arms. Report any difference in training recipe or checkpoint selection when interpreting gains.
- [ ] Pin the reference's L2 card, source artifact versions, label mapping, eligible slide IDs, tile counts, exclusions, and split assignment for both new arms. Reuse the labeled, nonempty slide eligibility in `ml/data/datasets/single_scale.py`. Reject duplicate slide IDs, nonfinite targets, and cross-split overlap. Check patient or case overlap when a verified grouping key is available and record whether grouping could be verified. Use the existing fixed L2 split if no comparable reference can be verified and report that the baseline comparison is inconclusive.
- [ ] Reuse CV if the reference runs used it and their folds are available through the existing data and training workflow. Pair methods by fold and seed and follow the existing checkpoint and reporting conventions. For fixed-split runs, use the existing train and validation artifacts and report seed variability on one split. Reserve the held-out test partition in either case.

**Acceptance.** The comparison notes in the Google Sheet identify the reference runs, matched data and split, and any comparability gaps. Confirm from membership metadata that test is held out ahead of scoring.

## 2. Add the projector and fixed recipe

- [ ] Add `TileProjector(in_dim, out_dim, dropout)` in `ml/models/encoders/tile_projector.py` and register it with the existing encoder package and Hydra group. Apply `Linear(2560, 256) → GELU → Dropout(0.20)` to each tile. Route the projected dimension to the aggregator and `LinearHead`, preserving 2,560 as the input width. Reuse `MeanPool` and `AttentionMIL`, with a 128-wide gating layer for ABMIL-attention. Add an opt-in identity normalization path to the attention aggregator for the new preset so both pooling arms pool the same projected values. Preserve the existing attention preset's LayerNorm default.
- [ ] Add opt-in scalar head initialization to `ml/models/heads/linear.py` and wire it into a fresh regression fit in `ml/train.py`. Use Xavier uniform with gain `0.01` and set the bias to the mean index of eligible training slides, read from dataset label metadata without decoding bags. Compute this separately inside each fit partition. Apply it only when requested, before training and after verifying the targets are finite. On resume or checkpoint evaluation, restore the saved head. Use zero head dropout for all fixed-recipe arms so projector dropout is the regularizer being varied.
- [ ] Add an opt-in training-only tile cap to `SingleScaleDataset`, drawing 1,024 distinct rows uniformly without replacement on every fetch and retaining every row in shorter bags. Sample before tensor conversion and device transfer. Seed the loader shuffle and tile RNG independently of model initialization. Use the same sampling stream for matched seed and fold across fixed-recipe arms, with fresh draws across epochs. Keep validation, test, and prediction uncapped even with a training cap in the resolved config. Train on four variable-length slide bags per optimizer step with equal weight per slide. Add a separate evaluation batch size of one through `ml/data/datamodule.py`. A Parquet read still decodes a full slide. Measure host I/O and peak device memory in the pilot before optimizing the loader. If full-bag evaluation exceeds memory, use exact chunked projection and pooling with a running sum/count for mean and a numerically stable weighted sum for attention.
- [ ] Add `configs/experiment/ml/train_mil_embeddings_abmil_mean_regression.yaml` and `configs/experiment/ml/train_mil_embeddings_abmil_attention_regression.yaml` as ordinary experiments that share Hydra components. Default both to `cancer_mask_5/l2` and `test_after_fit: false`. Use the usual `data/embedded` override if the reference pins a different L2 card. Share AdamW with `lr=1.5e-4`, `weight_decay=1e-3`, MSE training loss, and epoch-wise cosine annealing over 50 epochs to `eta_min=1e-6`. Save the checkpoint with lowest validation MAE, preferring the earlier epoch on a tie. Log the initial prediction mean and SD on a fixed training probe, training target mean and SD, early validation loss, optimizer steps, LR, and best epoch to the standard MLflow run.
- [ ] Add Hydra metric options for Spearman and sign-AUROC alongside MAE and MSE. Use the existing Lightning metric collection to log all four over each validation and test epoch. Compute Spearman on the continuous index and score. For sign-AUROC, use `target >= 0` as the positive class and rank by the continuous prediction. Check tied ranks, index zero, constant inputs, and single-class targets. Treat undefined ranking metrics as unavailable in the report.

**Acceptance.** Compose both presets and run a CPU fit, save, reload, and validation pass on synthetic variable-length Parquet bags through the usual entry point. Check that the output is scalar, the head starts near the training label mean, a restored head retains its bias, and a four-slide batch produces one optimizer update. Test that equal-mean bags can give different outputs after projection, sampling is repeatable with a fixed seed and changes across epochs, and a one-tile or oversized evaluation bag uses all its tiles. Confirm the standard validation run logs the four metrics and fit leaves the test loader untouched. If chunking is needed, compare full and chunked scores and attention on the same fixtures.

## 3. Launch ordinary training runs

- [ ] Launch the Hydra experiments with the usual `ml.train` command and existing job workflow. Use the same five seeds for both arms, preferring **0, 1, 2, 3, 4** when the reference covers them. Otherwise take up to five available reference seeds in ascending order and fill remaining slots with the lowest unused seed IDs. The core comparison uses 10 new fits on a fixed split. Example commands for seed 0 on the default L2 card follow.

  ```bash
  uv run -m ml.train +experiment=ml/train_mil_embeddings_abmil_mean_regression seed=0
  uv run -m ml.train +experiment=ml/train_mil_embeddings_abmil_attention_regression seed=0
  ```

- [ ] Use ordinary Hydra overrides for the one-factor sensitivity check on the first two frozen seeds per arm. Change one value per fit using `ml.encoder.out_dim=128`, `ml.encoder.dropout=0.35`, or `ml.optimizer.lr=2e-4`. This adds 12 fits on a fixed split. Keep model selection restricted to the nominal ABMIL presets and the historical reference.
- [ ] Check the resolved configs and `test_after_fit=false` before launch. Pilot with development data using the existing workflow to check memory, throughput and checkpoint logging. Record run IDs, source, seed, fold, and selected checkpoint in the Sheet. Review split integrity and checkpoint handling before the full experiment. Show the jobs, target context, namespace and affected scope, and obtain explicit approval before each cluster submission.

**Acceptance.** Each fit appears in MLflow as a normal regression run with the resolved Hydra config, validation metrics and a saved checkpoint. Resolve any missing checkpoint metric with the regular `ml.train mode=validate checkpoint=…` path.

## 4. Compare validation results by hand and check attention

- [ ] Copy MAE, MSE, Spearman, and sign-AUROC at each selected checkpoint from MLflow into the Google Sheet. Use ordinary spreadsheet formulas for **mean ± sample SD**, counts, and per-seed `ABMIL − historical linear` differences on verified matching seeds, cohorts, folds, and metric definitions. Use the archived baseline's identified validation checkpoint. If a baseline checkpoint is available and a metric is missing, use ordinary `mode=validate` with the new metric options. Mark unsupported cells unavailable. Show each seed, which pairs improved, and the sensitivity deltas. Interpret the differences as comparisons between complete training recipes.
- [ ] Run attention diagnostics at the nominal attention checkpoints with `ml.train mode=validate checkpoint=… +diagnostics=abmil_attention`. Adapt the patch-flipping procedure from `origin/feat/explainability` to the projected tile values for the scalar linear head. Check that weights are finite, nonnegative, and sum to one. Log the median per-slide effective tile fraction `1 / (N * sum(w²))`, top-decile attention mass, and slide coverage per seed. Use bags with at least 20 tiles for the concentration and faithfulness criteria.
- [ ] For deletion fractions 0%, 5%, 10%, 20%, 30%, 40%, and 50%, remove the same count of top-attention, bottom-attention, or randomly ordered tiles and renormalize over the retained tiles. Use at least 20 seeded random orders per slide. Define faithfulness as the area under the **absolute** change in index from the intact bag for top deletion minus the mean area for random deletion. Log this difference and the bottom-removal control with the model's validation diagnostics. Check the calculation on uniform/constant and high-attention signal fixtures. Read the resulting diagnostics manually alongside the four regression metrics.

**Acceptance.** The Google Sheet links each result to its MLflow run and checkpoint and shows the matched-seed differences. The attention diagnostics show whether weights depart from uniform and whether deleting attended tiles changes predictions more than random deletion.

## 5. Lock the validation decision and run test once

- [ ] Freeze the proposed go rule before reading ABMIL validation scores. Use the manual seed table to check for **at least 2% lower mean MAE** than the historical linear reference across at least **three matched seeds**, with improvement in at least **80%** of pairs. Require mean Spearman and sign-AUROC within **0.02** of the reference or better on those pairs. Missing or undefined guardrail metrics make the decision inconclusive. For ABMIL-attention also require the median of the five seedwise median effective tile fractions to be **≤ 0.90** and mean faithfulness to be positive in at least **4 of 5** seeds. Report the seed spread with the decision.
- [ ] Select the lowest mean validation MAE among qualifying arms, using the same paired seeds and preferring mean pooling on an exact tie. If the comparable results support a no-go for both, recommend retaining the historical linear configuration. If missing provenance, pairs, or metrics prevent a decision, report it as inconclusive and keep test closed. Report the deciding comparisons, seed spread, learning curves and attention diagnostics.
- [ ] Record the chosen resolved config, source and split, first prespecified paired seed, and checkpoint in the Sheet before test access. Use the saved validation-selected checkpoint on the fixed split or follow the verified CV protocol's final fit procedure. For a retained historical reference, reuse its stored held-out result if the checkpoint, split, and metric definitions match. If a fresh test score is needed, run `ml.train mode=test checkpoint=…` once for the locked config after explicit cluster approval if required. Record test MAE, MSE, Spearman, and sign-AUROC once from the standard MLflow evaluation.
- [ ] If the L1 task succeeds, repeat the frozen validation benchmark on its registered artifacts. For a resolution comparison use the shared-slide, matched-bag L2 control defined in the L1 plan. Keep the L2 decision and single test evaluation intact.

**Done.** Both ABMIL presets run end to end. Validation results include five-seed summaries, the comparison to existing Google Sheet runs, paired differences where supported, and sensitivity checks. The report gives the attention diagnostics and the go/no-go decision. The held-out report covers the single locked setting if validation supports a decision.
