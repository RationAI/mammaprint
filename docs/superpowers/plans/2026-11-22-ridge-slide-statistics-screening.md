# Ridge-regression screening on cached slide statistics implementation plan

**Goal** — Establish a deterministic CPU ridge baseline and quantify how resolution, masks, pooling statistics, and training-set size affect MammaPrint index prediction.

**Architecture** — Read the existing Virchow2 slide Parquets once into a versioned cache. Run repeatable nested CV on cached development features, then refit and score the single locked configuration on the held-out test set.

**Inputs** — The ridge-screening task brief, `configs/data/embedded/`, the canonical `data_mapping.csv`, and the [L1 resolution plan](2026-11-22-l1-resolution-comparison.md). Python 3.12, PyArrow, NumPy, SciPy, scikit-learn, and the existing MLflow artifact workflow.

### B. Nested CV and the screening CLI

**How the folds work.** Suppose a screen has 100 eligible records in the existing train+val pool. A record can contribute multiple slides. Grouping by `record_num` keeps its slides together, and stratification aims for a similar mix of negative and nonnegative index labels across folds. Actual counts can vary with group size and class balance.

1. **Outer split measures performance.** For one seed, divide the 100 records into five folds of roughly 20. Hold one fold aside for scoring and use the other four, roughly 80 records, as the outer training pool.
2. **Inner split chooses α.** Divide only those 80 records into three folds. For each α, fit on roughly 53 records and validate on roughly 27, rotating through all three inner folds. Choose the α with the lowest average inner MAE. Refit with that α on all 80 records and score the 20 outer records once. Each outer fold can choose its own α.
3. **Repeat and pair.** Rotate the outer holdout so every record is scored once per seed. Repeat with five fixed seeds for 25 outer-fold scores per feature set. Use identical partitions across feature sets on the same cohort, so each paired difference compares predictions on the same slides. The repeats reuse records, so the standard errors account approximately for overlapping fits.
4. **Keep the existing test split reserved.** The folds above come entirely from train+val. After choosing the features, tune α within train+val again, fit once on the full eligible development pool, and score the original test split once. The historical sanity check separately uses the original train→validation split to match the lead run.

### C. Run the screens and choose a candidate

| Screen | Arms and control |
