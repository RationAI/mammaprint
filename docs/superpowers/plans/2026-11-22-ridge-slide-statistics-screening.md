# Ridge-regression screening on cached slide statistics implementation plan

**Goal** — Establish a deterministic CPU ridge baseline and quantify how resolution, masks, pooling statistics, and training-set size affect MammaPrint index prediction.

**Architecture** — Read the existing Virchow2 slide Parquets once into a versioned cache. Run repeatable nested CV on cached development features, then refit and score the single locked configuration on the held-out test set.

**Inputs** — The ridge-screening task brief, `configs/data/embedded/`, the canonical `data_mapping.csv`, and the [L1 resolution plan](2026-11-22-l1-resolution-comparison.md). Python 3.12, PyArrow, NumPy, SciPy, scikit-learn, and the existing MLflow artifact workflow.

## 1. Freeze sources, membership, and lead-model provenance

- [ ] Resolve the embedded cards into a sorted source inventory keyed by `(level, mask)`. Start with L2–L5 across `cancer_mask_5`, `cancer_mask_9`, `tissue_only`, `epithel`, `epithel_and_cancer_5`, and `epithel_or_cancer_5`. Verify actual availability and pin the `uris.all` artifact for each card. Add registered L1 sources when task 2 publishes its data card and verified URIs. Record each unavailable source and why. Include L1 sampling, stride, and mask provenance when interpreting resolution effects.
- [ ] Join Parquet stems to `data_mapping.csv` using the `Path(path).stem` convention in `ml/data/datasets/labels.py`. Preserve `record_num` as a string and use `mammaprint_index` as the continuous target. Keep the existing `split` as the test boundary and pool `train` and `val` for screening. Fail the affected run on duplicate stems, unknown split values, missing record IDs on mapped slides, or any `record_num` shared between test and development. Record source stems absent from the mapping and development exclusions for missing or nonfinite labels. Project membership columns for ingestion so test labels stay outside the cache and development entry points.
- [ ] Identify the historical L2 cm5 slide-mean regression runs behind the reported 78.0–81.3% F1 range. Save run IDs, seeds, code revision, resolved Hydra configs, checkpoint selection rule, exact train/validation artifacts, slide membership, and archived validation metrics or predictions. Verify target and prediction sign thresholds, tile eligibility, and the feature transform at inference. The current preset wires `IdentityEncoder → MeanPool → LinearHead`, and `MeanPool` averages the stored vectors directly. LayerNorm appears in other aggregators. Verify the archived lead config and checkpoint before choosing its parity features.

**Acceptance** — A pinned manifest accounts for all cards, the development/test boundary is disjoint by record, and the sanity check has a traceable historical reference or an explicit provenance blocker.

## 2. Build and publish the slide-statistics cache

- [ ] Add `preprocessing/slide_statistics.py` with `build_cache(config, output_dir) -> Path`, returning the published manifest. Reuse the repository’s MLflow artifact resolver for staged sources and support local directories for fixtures and cluster staging. Process one source at a time in stable slide order. Stream the `embedding` column from each per-slide Parquet in bounded batches. Accumulate per-coordinate mean and population variance in float64 using mergeable running moments. For each tile, apply affine-free LayerNorm across its full 2,560-element vector with `eps=1e-5`. Accumulate raw and LayerNormed statistics from the same tile batch. Store means and population standard deviations as float32 vectors and the original tile count as an integer. A one-tile bag has zero standard deviation. If the checkpoint audit identifies a different transform, pin its details for parity before the full pass.
- [ ] Publish `manifest.json`, paired `stats/dev/<level>/<mask>.parquet` and `stats/test/<level>/<mask>.parquet` partitions, and `coverage.parquet`. Store one statistics row per `(level, mask, slide_id)` with `mean_raw`, `std_raw`, `mean_ln`, `std_ln`, and `tile_count`. Record source presence and status per expected slide, including absent, empty, unreadable, invalid-vector, and unmapped cases. Keep missing entries out of feature matrices and include reasons in the report. Record schema version, source identity and file inventory, membership digest, transform and accumulation settings, code/runtime versions, and output checksums in the manifest.
- [ ] Stage writes atomically with per-source or per-shard completion markers tied to input identity. Resume verified work from those markers and retry transient read failures. Publish a completed manifest after inventory reconciliation. Use existing cluster-adjacent storage and CPU resources. Run a small development-only pilot to measure input bytes, throughput, memory, and scratch needs before the full pass. Keep tile subsampling optional and disabled by default. If enabled, cap the configured number of tiles per slide via a seeded stable rank of source row IDs and persist the IDs and raw vectors in a separately versioned sidecar.
- [ ] Create `.agents/skills/ridge-slide-statistics-screening/SKILL.md` with the reusable cache and evaluation commands, source authentication and target checks, local fixtures and dry-run, runtime sizing, publication evidence, retries, and cleanup. Prepare the cluster job locally and show the submission, context, namespace, and read/write scope for explicit approval before submission. Independently review the cache, data boundary, and reproducibility controls before the full run.

**Acceptance** — `tests/preprocessing/test_slide_statistics.py` checks batched statistics against direct NumPy/PyTorch results, including constant vectors, a one-tile bag, bad widths, nonfinite values, and empty or missing files. An interrupted synthetic build resumes to the same cache, and input drift invalidates stale completion markers. The real cache reconciles every expected slide against its status and has a versioned artifact URI or durable path.

## 3. Implement nested CV and the config-driven CLI

- [ ] Add `ml/ridge_screening.py` for feature joins, fold construction, nested fitting, and result aggregation. Add `scripts/ml/run_ridge_screening.py` and `configs/sweeps/ridge_screening/screening.yaml`. Expose `cache`, `sanity`, `screen`, `lock`, and `test` subcommands. The `screen` mode takes `--screen levels|multilevel|statistics|masks|learning-curve|all`, `--config`, and `--output`; a dry-run inventories inputs and planned contrasts. Declare directly imported scientific dependencies in `pyproject.toml` and update `uv.lock` using the current resolved versions where compatible. Keep the CLI CPU-only and independent of the Lightning trainer.
- [ ] Join features on exact slide IDs. For each screen build a common complete-case development cohort across its arms and the L2 cm5 LayerNormed mean reference, and freeze its ordered slide and record IDs. Generate one shared fold ledger for that cohort. Publish exclusions and all-available coverage for each arm. Use the complete-case intersection across ranking candidates for a single overall ranked table. If that intersection cannot support the protocol, use the prespecified core ranking cohort of L2–L5 cm5 means, L2 cm5 mean+std, and the L2+L3 cm5 concatenation. Report remaining arms on their own matched cohorts and keep final selection within the common ranking cohort. If the core cohort also fails, stop selection and report the blocker.
- [ ] Default to **five outer folds for each of seeds 0–4** and **three inner folds**. Use `StratifiedGroupKFold` with `record_num` as the group and `mammaprint_index >= 0` as the stratum. Sort inputs, derive inner seeds from the configured seed and outer fold, and persist the split ledger. Assert record disjointness and check class counts in all folds before fitting. If a valid split cannot be constructed, report the infeasible cohort with its class and group counts. Keep all slides from a record together and use the lead model’s equal-slide weighting for fit and metrics. Report slide and record counts so the unit of analysis is clear.
- [ ] Fit float64 ridge with an intercept over positive `alpha = 10**k` for `k = -6, …, 6`. Center features and labels using each fit partition, with no variance scaling. Compute one thin SVD per fit partition and reuse it across the alpha grid with the ridge shrinkage factor `s / (s² + alpha)` for each singular value `s`. Verify predictions against `Ridge(solver="svd", fit_intercept=True)` on wide and rank-deficient fixtures. Select alpha by smallest mean inner-validation MAE, breaking ties toward the larger alpha. Use the same inner splits for arms on the same fit roster. Refit on the outer training partition and predict its held-out fold. Pin numeric package versions and thread settings.
- [ ] Write `folds.csv`, `metrics.csv`, `contrasts.csv`, and `run.json` with cohort and input hashes. Record `(screen, cohort, feature_set, seed, fold, fraction)`, chosen alpha, train/assessment counts, and each metric. Use slide MAE, Spearman on the continuous scores, and AUROC of continuous scores against `index >= 0`. Represent undefined metrics as missing with a reason and a valid-fold count. Compare only matching assessment slide IDs and fold IDs. Report arm minus reference, where negative is better for MAE and positive is better for Spearman and AUROC.
- [ ] Report the mean across outer folds and an approximate overlap-adjusted SE, `sqrt((1/m + r) * s²)`, where `m` is the valid fold count, `s²` is the sample variance of fold scores or paired deltas, and `r` is the mean outer assessment-to-fit record count ratio. For a learning-curve contrast use the smaller fit size in the ratio. Report missing SE when fewer than two folds contribute. Label these as descriptive screening estimates because folds reuse records. Preserve per-fold results for audit. [Nadeau and Bengio, *Inference for the Generalization Error*](https://papers.nips.cc/paper_files/paper/1999/hash/7d12b66d3df6af8d429c1a357d8b9e1a-Abstract.html)

**Acceptance** — `tests/test_ridge_screening.py` checks multi-slide records, no mixing of test and development records, exact fold/slide pairing, inner-only selection, handling of single-sign or constant inputs, sign-zero treatment, and paired SE against a hand calculation. Run a synthetic config twice and compare sorted numeric tables, selections, and fold ledgers exactly in the pinned environment.

## 4. Clear the L2 cm5 sanity check before screening

- [ ] Run `sanity` on the lead model’s original train→validation comparison with the same eligible slides, tile selection, label mapping, and metric definitions. Select alpha by inner CV on the original training slides. Fit the lead-matched mean features and include the LayerNormed mean as a sensitivity check when the lead used raw features. Verify checkpoint predictions against its linear head applied to the matching cached mean on a fixture and a development slide sample. Check historical split overlap by record and document any limitation on the comparison.
- [ ] Compare slide MAE and sign-threshold F1 (`prediction >= 0`, `target >= 0`) with the historical validation seeds. Freeze a practical tolerance before seeing ridge results. The proposed default flags F1 more than two percentage points below the verified historical minimum or MAE more than 5% above the historical seed mean. Report the ridge value, seed range, and cohort counts. Treat the quoted F1 range as context until its split and metric are confirmed. If parity is unresolved or ridge falls short, diagnose source and cohort mismatches, tile normalization, label and threshold conventions, and shrinkage or optimizer differences before launching screens. Record the explanation and rerun the matched check after corrections. Require the resolved `sanity.json` when executing a production screen and verify the L2 cm5 source, mapping, and transform identities against it.

**Acceptance** — `sanity.json` records reference provenance, cohort, numerical parity checks, metrics, and the decision to proceed. Screening starts after the sanity check is resolved.

## 5. Run the screens and produce the development report

| Screen | Arms and control |
| --- | --- |
| Levels | cm5 mean at L2, L3, L4, and L5. Include L1 cm5 once registered. Use L2 cm5 mean as control. |
| Multilevel | Concatenate L2+L3 cm5 means by slide ID and add L1+L2 after L1 registration. Compare against L2 on the same slides. |
| Statistics | L2 cm5 mean versus L2 cm5 mean+std, using the same tile transform in both arms. |
| Masks | Compare the six registered L2 masks with mean features and L2 cm5 as control. |
| Learning curve | L2 cm5 mean on 25%, 50%, 75%, and 100% of each outer training pool, by record. |

- [ ] Run each screen once from the pinned config. Use LayerNormed features consistently for the representation screens. If the sanity check establishes raw means as the historical match, include the raw L2 cm5 mean as an additional baseline on the ranking cohort. When L1 arrives, extend the cache with its source partitions and rerun affected development screens. Select the test candidate only after deciding which available sources enter the freeze.
- [ ] For the learning curve, order outer training records deterministically within their majority-sign stratum, breaking sign ties toward nonnegative. Use nested prefixes at the four fractions and include all slides for each selected record. Recompute inner folds and tune alpha using that fraction’s training records only. Use identical outer assessment slides at every fraction. Report realized record counts, the 75%→100% paired change with SE, and whether the curve suggests continued gain, a plateau over the observed range, or insufficient precision to tell.
- [ ] Generate `report.md` and a learning-curve plot from the emitted tables. Rank common-cohort candidates by mean outer MAE, breaking exact ties by fewer feature coordinates and then stable feature ID. Give MAE, Spearman, and sign-AUROC as mean ± SE and paired deltas from the LayerNormed L2 cm5 mean. Include cohort sizes, exclusions, sanity evidence, and the coverage tradeoffs behind the recommendation. Recommend a ridge baseline and the level/mask inputs for option 4, with the matched evaluation cohort option 4 should use. Interpret a flat ridge curve as evidence about these slide summaries over the measured range.

**Acceptance** — The report links to the cache and fold ledger, every rank and contrast is traceable to shared assessment slides, and the learning curve shows uncertainty and realized sample sizes.

## 6. Lock the final configuration and evaluate test once

- [ ] Have `lock` write the winner’s feature definition, cache and mapping digests, frozen ranking tables, development and test membership rules, and the test metric specification. Refit using all eligible train+val records for the frozen feature definition, tuning alpha with grouped inner CV on development data only. Save the selected alpha, intercept, coefficients, and lock digest before joining test labels.
- [ ] Require the lock and frozen model in `test`. Score the test partition once and write `test_metrics.json` with MAE, Spearman, sign-AUROC, coverage, and the lock digest. Claim the evaluation in a durable run directory. Repeated invocations return the saved result, or finish publishing a previously saved prediction payload after an interrupted write. Keep test-feature eligibility fixed by the winner’s required source blocks and report all exclusions. Append the result to the report. Any L1 arrival after this evaluation is a development-only update for this task.
- [ ] Independently review the cohort, folds, sanity gate, and test lock before opening test. Run `uv run pytest -q tests/preprocessing/test_slide_statistics.py tests/test_ridge_screening.py` and a synthetic CLI run that verifies the development commands never open test data, and that `test` rejects a missing or mismatched lock. Verify the real cache manifest and rerun the development evaluation from the same inputs to confirm identical numbers. Commit each verified logical change with its owned files, keeping reusable remote scripts and their skill versioned together.

**Done** — A reusable versioned cache accounts for available sources and missing slides. The CLI reproduces the screen tables and paired results. The report documents the historical sanity check, feature ranking, learning curve, recommended ridge baseline and option 4 inputs, and the single locked test result.
