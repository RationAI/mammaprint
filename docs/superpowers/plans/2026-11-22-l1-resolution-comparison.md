# L1 Virchow2 resolution comparison implementation plan

Test whether 20× L1 improves MammaPrint index prediction over 10× L2 at the same per-slide tile count. Use existing cancer-mask coordinates and L2 embeddings, embed a capped L1 sample once, then compare the current regression model on the existing validation split. Exclude re-tiling, L0, stain augmentation, and architecture changes.

## 1. Freeze the tile selection and expected slide inventory

- [ ] Inspect `slides.parquet` and `tiles.parquet` from the existing L1 and L2 cards in `configs/data/tiled/cancer_mask_5/`. Verify source run provenance, slide IDs, pyramid levels, physical scale, per-slide stride and tile footprint, coordinate origin and units, and mask thresholds. The level configs specify 224 px tiles and 112 px stride at each target scale. Use the realized source geometry for grid filtering.
- [ ] Implement selection in `preprocessing/embedding_selection.py`. Keep every other grid position on both axes with a fixed origin and phase. Check edge behavior against the original `grid_tiles(..., last="keep")` convention and verify that retained footprints do not overlap. The grid retains roughly one quarter before mask and edge effects. Account for observed deviations per slide.
- [ ] Set the maximum to **3,000 tiles per slide** and the sampling seed to **42**. Rank eligible coordinates with a stable seeded hash of the canonical slide ID and integer coordinates. Keep the lowest ranks with a coordinate tie-breaker, then order the selected rows spatially for WSI reads. Persist ranks so smaller subsets are reproducible. Freeze the selection before comparing validation performance.
- [ ] Project and preserve `tissue_overlap`, `blur_overlap`, `folding_overlap`, `residual_overlap`, `cancer_overlap`, and `epithelium_overlap`. Check the stored columns and missing-value counts. If a score is absent, recover it from the pinned mask source on the selected coordinates using the original scoring convention. Record unavailable scores explicitly and publish any resulting limits on derived masks. Derived masks can only select from the retained sample and the original cancer/QC gates.
- [ ] Write an input manifest with source URIs, source and grid tile counts, selected coordinate/score Parquets, split-map digest, selection version, and per-slide selection digests. Stream projected Parquet columns and build slide partitions once so workers do not scan the full tiling artifact. Validate unique stems and coordinate keys. Give every expected source slide a manifest entry, including zero-tile slides, and reconcile source slides against `data_mapping.csv`.
- [ ] Prepare the L2 control from `configs/data/embedded/cancer_mask_5/l2.yaml`. Join its precomputed coordinate keys to the L2 source metadata and apply the same mask eligibility, grid rule, seeded ranking, and cap. Account for any coordinate mismatches before training. If coverage cannot be verified, report the affected slides and resolve the source discrepancy before treating L2 as a matched control.

**Acceptance.** On a fixture with nonzero origin, distinct X/Y strides, clipped edge positions, shuffled rows, and sparse slides, grid footprints are disjoint, the selected tile IDs and scores are stable, and the 3,000-tile cap holds. On the real artifacts the manifest accounts for every source slide and records measured tile counts for cost estimation.

## 2. Make L1 embedding resumable and benchmark it

- [ ] Run the manifest-backed worker in `preprocessing/resolution_embeddings.py`. Reuse the `ratiopath` WSI reader and the 2,560-dimensional Virchow2 CLS-plus-mean-patch extraction from `preprocessing/embeddings.py`. Pin the encoder weights revision, runtime image and software revision. Verify compatibility with the L2 artifact and record any provenance gaps before interpreting the result.
- [ ] Build a deterministic slide-to-shard assignment, balancing by selected tile count with a per-slide overhead estimate from the pilot. Schedule one writer per shard on durable shared storage. Use a versioned output root keyed by the manifest and encoder configuration. Write one Parquet per slide with `x`, `y`, `embedding` and the six score columns. Verify row count, coordinate alignment, score alignment, and finite 2,560-element embeddings, then publish atomically with a completion record. Resume only when the file and record match the expected selection and configuration. Keep a structured attempt log and retry failed or missing slides from the same manifest.
- [ ] Tune for a full A40. Start at batch size 1,024 with eight WSI workers and two prefetched batches per worker. Reuse those workers across slides, combine short slide tails into full GPU batches, sort coordinates for read locality, and use pinned host buffers with nonblocking CUDA transfers. Keep Parquet publication off the inference loop with a bounded writer queue. Request CPU, host RAM and shared memory against the in-flight loader footprint as well as slide decode needs.
- [ ] Sweep batch sizes 512/1,024/1,536 and worker counts 4/8/12 in a bounded pilot. Benchmark BF16 autocast on the same tiles against the float32 L2-compatible reference, including embedding agreement, throughput and peak VRAM. Keep float32 as the default until precision compatibility is verified and approved for the experiment. Choose the fastest stable profile by committed tiles/sec, with VRAM and host memory headroom for large slides. Log GPU utilization separately with `nvidia-smi` and use loader wait versus CUDA timing to decide whether to tune storage, CPU or GPU next.
- [ ] Use `scripts/preprocessing/run_resolution_embeddings.py` to render and run the bounded A40 pilot from an approved allocation. Run the shard worker explicitly with its storage root, manifest and shard ID. Verify context, namespace, image, resources, and write paths before submission. Use cluster-managed credentials. Follow the [cluster runbook](../../../.agents/skills/l1-resolution-comparison/SKILL.md) for target checks, commands, expected evidence, retry and cleanup steps.
- [ ] After explicit approval, run a small single-pod pilot on representative train/validation WSIs spanning file formats, slide sizes, and tile counts. Time WSI open/read/decode and loader waits, host-to-device transfer, synchronized GPU inference, and write/upload. Record GPU utilization, peak memory, end-to-end tiles/sec, slides/hour, and failure causes. Compare a bounded set of worker counts and batch sizes using spatially ordered reads. Measure warm and cold behavior. Exercise interruption and resume. If WSI reads dominate, try local staging where allowed and measure whether it pays off.
- [ ] If the full run needs multiple pods, show and obtain approval for a bounded concurrent pilot. Use its aggregate rate to check shared-storage contention. Project wall time, GPU-hours, staging/network use, and durable storage from the actual manifest and pilot measurements. Budget for slide overhead and retries. The historical L2 rate of about 46 tiles/sec implies about 96 single-GPU hours for 15.75M tiles before capping, assuming equal throughput. At float32 the feature vectors alone take 10.24 kB per tile before compression and artifact copies.

**Acceptance.** A restart after a partial write reprocesses only unfinished or invalid slides. A second invocation reuses validated results. Shards cover the manifest exactly once. The pilot report identifies the main bottleneck and recommends a measured batch size, worker count, shard count and GPU-hour budget. Show the exact full-run submission, target and projected cost for explicit approval before launch.

## 3. Complete and register the embedding datasets

- [ ] Run the approved full L1 workload and reconcile the union of shard outputs against the manifest. Retry recoverable errors. Publish counts and remaining slide IDs with split, reason, and attempt history for zero eligible tiles, missing slide data, and processing failures. Check Parquet integrity and score/coordinate alignment before registering any dataset.
- [ ] Use `preprocessing/resolution_data.py` to reconcile `data_mapping.csv` and resume MLflow uploads on the same run. Register L1 `all`, `train`, `val`, and `test` directories as verified MLflow artifact URIs. Record slide/tile counts and check that all successful slides appear exactly once across the three splits. Keep the split and failure manifests outside directories expected to contain only per-slide Parquets.
- [ ] Add `configs/data/embedded/cancer_mask_5/l1.yaml` with the verified MLflow URIs and publish an L1 data card with the source, geometry, masks and score availability, sample rule and seed, encoder revision, split-map digest, tile/slide counts, cost and failures. Load a train or validation bag through `SingleScaleDataset` to verify compatibility with the score columns.
- [ ] Build comparison-only L1 and L2 split views from the registered embeddings. Use the same nonempty, labeled slide IDs at both levels within each existing split. For each shared slide take the first `min(3000, eligible_L1, eligible_L2)` tiles in the frozen ranking at each level. Publish those tile counts and all exclusions. Slide identity and bag size are matched, and physical coverage differs with tile footprint. Inspect test membership and file integrity during registration. Reserve test labels and predictions for the final evaluation.

**Acceptance.** Source inventory equals validated L1 outputs plus explicitly documented exceptions. All expected split artifact files and provenance are verified in MLflow. Comparison manifests show identical slide IDs and per-slide bag sizes by level, with no cross-split slide leakage.

## 4. Train and report the paired validation comparison

- [ ] Use `scripts/ml/run_resolution_comparison.py` to render the fixed matrix and run the requested fits within approved allocations. Reuse `ml.train`, `configs/experiment/ml/train_mil_embeddings_regression.yaml`, and the mean and attention Hydra aggregators. Run **12 fits** across L1/L2, mean/attention, and training seeds **0, 1, 2**. Use the frozen data views, identity encoder, linear head, MSE, and the same optimizer, schedule, batch size and stopping/checkpoint policy. Use the existing `valid/loss` checkpoint monitor in every cell. Record the resolved config, split digests, code revision, run IDs and best checkpoints.
- [ ] Require `test_after_fit=false` for every comparison job because `configs/ml.yaml` enables it by default. Have the launcher verify all resolved configs and test a fit with a test-loader stub that fails if invoked. Evaluate validation checkpoints explicitly with the validation loader. The current `mode=predict` path resolves to the test loader.
- [ ] Add `scripts/ml/evaluate_resolution_comparison.py` to export one raw score per slide per checkpoint. Verify unique slide IDs, matching labels and exact cohort coverage across runs. Calculate MAE on the continuous index, Spearman on the index and raw score, and sign-AUROC on `index >= 0` with the raw score as the ranking input. Exercise tied scores, index zero, missing predictions, and one-class inputs in local metric tests.
- [ ] Publish a validation table with one row per pooling method and level. Include validation slide count and MAE, Spearman, and sign-AUROC as **mean ± sample SD across seeds**. Add the L1−L2 deltas for each matched seed and pooling method, plus a 95% paired bootstrap CI for each seed-averaged delta. Resample the same validation patients when IDs are available, or slides otherwise, across both resolutions and all seeds. State the resampling unit and that these intervals are conditional on the trained seeds. Report sparse-bag counts, and optionally score nested 1,000/2,000-tile subsets on validation to diagnose sensitivity to tile count.

**Acceptance.** All 12 logged runs have complete validation predictions on the same cohort. Paired metrics reproduce from the saved predictions and cohort digest. Synthetic end-to-end evaluation verifies that comparison jobs never enter the test loader.

## 5. Lock the decision and evaluate test once

- [ ] Freeze the decision rule before inspecting validation scores. Use mean pooling for the primary fixed-pooling comparison and attention as the second paired comparison. The proposed go rule requires the upper bound of the mean-pooling MAE delta CI to be below zero, the lowest-mean-MAE L1 setting to improve by at least **2% relative** over the best L2 setting, and the L1 setting to lose at most **0.02 absolute** on each of Spearman and sign-AUROC. Require the measured L1 cost to meet the budget agreed at the full-run approval. Otherwise choose L2. Report both pooling comparisons, cohort exclusions, budget evidence and the decision rationale.
- [ ] Lock the chosen resolution, its lowest-validation-MAE pooling method, seed **0**, and that run's best checkpoint, along with the test cohort and tile manifest digests. Use mean pooling to break an exact pooling tie. After explicit approval if a cluster job is needed, run one held-out evaluation of that checkpoint on the locked test view and report MAE, Spearman and sign-AUROC from the single prediction pass. Keep the test result out of model selection.
- [ ] Review the selection, resume and split logic independently before the full embedding run, and the benchmark configuration and evaluation split guards before submitting training or test jobs. Verify the reusable scripts and skill with local fixtures and dry-runs, then record remote evidence for the approved stages. Commit each coherent implementation change with its verification and keep the scripts and their skill versioned together.

**Done.** MLflow links resolve to the L1 data card and verified split artifacts. The slide inventory lists every exception. The validation report contains both paired pooling comparisons and the go/no-go decision. Exactly one successful test evaluation is recorded for the locked setting.
